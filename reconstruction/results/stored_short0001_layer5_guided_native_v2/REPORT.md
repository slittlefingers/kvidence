# 第二轮执行优化：109-token 密文恢复

同一 Gemma 4 E2B / Pixel 10 NPU / 数据库 0001 第 5 层观测，guided 在线时间 **117.365 → 95.636 秒**，耗时减少 **18.51%**（本次约 1.23 倍）。相对最初文件通信版的 610.764 秒，累计约 6.39 倍。仍为 **109/109 正确**，16,530 个候选、388 次物理候选调用。

## 等价性

与上轮逐位置比较：查询 ID 序列、次数、选中 token、接受的原始 KV 字节、全部已查询候选的距离、阶段记录、接受/提交距离及 commit/query 一致性，全部相同。模型、观测、完整 262144 词表、逻辑 batch=256/物理 128、50+150 初始种子、20 个 ridge 提议、seed=20261019、原始拼接 K+V L2<4 均未改变。

独立评估见 [evaluation.json](evaluation.json)，全部已查询候选距离及轨迹的一致性检查见 [v2_comparison.json](v2_comparison.json)。输出依然是 156-byte 密文表示，没有解密出原始 LMSYS 明文。目标标签只用于事后评估，恢复沿用自己的前缀。

## 改动和效果

- **embedding 批输入缓冲区复用**：各槽位覆盖写，避免每批创建/释放同尺寸的大数组；填充规则不变。
- **1024 项 LRU 缓存**：满时只淘汰最久未访问项，替代整张清空；不增大缓存容量。在线 embedding miss 从 12,128 降到 11,164。准备/拼装大幅提速不能全部归因于少算 embedding，还包含缓冲区复用和分配减少。
- **精确完整排名的 radix sort**：与原稳定数值降序/同分 ID 升序相同，包含正负零处理。仍返回全词表，不减少排名 payload。
- **主机精确前 k 选择**：ridge 分数不变，用 partition + 边界并列处理，最后仅对选中的 k 项排序，输出与原全量 lexsort 前 k 项一致。

## 验证与边界

50 项主机测试通过，包括原生 radix 对照稳定排序（全词表、重复分数、正负零、有限极值和非有限值拒绝）以及精确部分选择对照全排序。主机选择步骤独立微测为 21.025 → 2.276 ms；这个比例不能当作完整 ridge 或恢复加速比例。

[同 APK 设备对照](../native_v2_validation_20261019/validation.json)验证上一版/v2 的完整排名、不同候选 batch、重复查询、跨物理批 CPA 保留提交、提交后查询、不同等长前缀重置，以及 1100 个不同候选触发缓存淘汰后的结果，KV 与排名均一致。

最终 APK/optimized_v2 的独立已知文本 8 位置 × 1024 候选 pilot 已重新采集，阈值与历史资产一致：[CPA pilot](../../assets/cpa_gemma4_pilot_native_v2/calibration.json)。仍需 `--allow-pilot-calibration`，不是正式全文全词表校准。本报告最初仅完成 CPA 三 token 集成验证；随后已完成同一密文的两方法各两次交替重复，见 [最新成对对比报告](../stored_short0001_layer5_cpa_vs_guided_native_v2/REPORT.md)。此处保留单方法优化记录，当前速度比以新报告为准。

本报告完整耗时比较是各一次历史/当前运行，未做随机交错重复；频率、热状态及调度可能影响结果。18.51% 是本样本观测值，不保证其他模型/输入同样提速。改动说明见 [NATIVE_OPTIMIZATION_V2.md](../../NATIVE_OPTIMIZATION_V2.md)。

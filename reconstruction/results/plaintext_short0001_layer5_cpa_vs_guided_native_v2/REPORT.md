# 未加密 prompt：第 5 层 KV 恢复对比

日期：2026-10-19（Australia/Melbourne）。Pixel 10 / Gemma 4 E2B / NPU，使用上一条密文样本 0001 对应的原始明文，原样作为 user prompt 输入 Ghost，生成回复后采集真实 KV。CPA 与 guided 各运行两次，顺序为 CPA → guided、guided → CPA。恢复完成后才使用独立真值评价。

## 输入与采集

原文（87 UTF-8 bytes）：

> write an email to my boss saying i want leaves for the next 10 days for vacation in goa

这条自然英文 prompt 为 **21 个目标 token**；对应密文为 109 个。原文没有补长、截断或添加存储问题外壳。公开前缀只有 4 个聊天模板 token，目标为第 5 层 producer（索引 4）的 KV 位置 4–24。完整模型输入含模板共 30 token；回复后的快照有 541 个已消费 KV 位置，恢复目标仍仅为原始 prompt。

采集调用耗时 34.817 秒，导出/压缩 0.483 秒；这些不计入恢复在线时间。沿用 512 output-token 上限，不根据回复猜输入。原始 allocation 经无损 gzip 保存，30 个 INT8 KV 缓冲区通过哈希、CRC 和布局检查；采集来自进程拥有的 NPU TensorBuffer 映射，并非任意物理 DRAM 扫描。

明密文对应关系通过准备阶段的 AES-GCM 认证解密核验；密钥和原文均不送给恢复执行器。公开模板的 3 个非 BOS 位置与真实观测 K/V 距离均为 0，见 [前缀验证](../../experiments/plaintext_short0001_layer5/prefix_validation/validation.json)。恢复过程中始终使用自身恢复的前缀，不装入真实目标前缀 KV。

对应密文结果见 [先前报告](../stored_short0001_layer5_cpa_vs_guided_native_v2/REPORT.md)。两组使用相同模型、APK、运行库、核心搜索/原生执行源码、原词表、embedding 提议资产、随机种子及 CPA 校准资产；这些身份已经逐项核对。此次仅新增实验准备脚本，没有修改恢复算法。

这不是严格隔离加密变量的消融：明文更短、公开前缀从 11 个 token 变为 4 个，并去掉了密文外层的存储问题；即使除以 token 数，位置、前缀长度及模型概率分布仍不同。因此只比较这个配对样本的观察结果，不声称任意自然文本都更容易恢复。

CPA 按逻辑 256 个候选为批次，guided 的概率阶段最多 50 个，之后可加 150 随机种子及每轮 20 个 ridge 提议。若正确 token 已在概率候选内，两方法最小完整验收批次不同，本身就造成候选数差；不能将这一差距全部归功于 ridge 引导。物理 NPU 签名固定 128 槽，有效候选数也不是硬件实际执行槽数。

## 本次观察到的具体原因

第二个 token 的对照尤其明确：CPA 与 guided 都已查询到 ` an`（ID 614），其 KV 距离为 **0**；排名更靠前的 ` a`（ID 496）距离为 **7.873577**。CPA 的当前 pilot 阈值让两者都通过，按官方规则接受概率序中首个通过者，因此选中 ` a`。guided 的 L2<4 排除了 ` a`，选中 ` an`。这次误接受不是“没搜索到真 token”，而是当前阈值和接受顺序的结果，见 [候选证据](acceptance_evidence.json)。错误候选 K=0.346119、V=7.865965，均低于 CPA 当前有效阈值；这不证明完成正式校准后还会出现相同错误。

CPA 后续 19 个 token 的 ID 仍正确，但接受距离为 1.551644–7.980793；其前缀已包含 ` a`。本样本观察到前缀错误伴随后续 KV 偏差，不能推广为错误不累积的保证。guided 全部接受距离为 0，87-byte 原文逐字节一致。

明文中 guided 有 **18/21（85.71%）** 个位置在概率阶段通过，3 个位置需要 ridge；对应密文为 **59/109（54.13%）** 个概率阶段位置、50 个 ridge 位置。三处 ridge 目标及实际查询数为：

| 原文位置 | token | CPA 候选数 | guided 候选数 |
| --- | --- | ---: | ---: |
| 1 | `write` | 13,056 | 340 |
| 10 | ` leaves` | 512 | 280 |
| 21 | ` goa` | 4,352 | 300 |

CPA 的 `write` 和 ` goa` 两个位置占全部候选的 **76.40%**，所以“普通英文”不意味着每个 token 都排在概率前列。guided 在这三个位置用了引导提议；其中 ` leaves`、` goa` 的 CPA 前缀已经有误，不能把该两处差额视为完全相同前缀下的搜索消融。首位置 `write` 的公开前缀相同。

guided 的平均查询从密文约 **151.65/token** 降至明文 **86.67/token**；CPA 则从约 **901.87/token** 升至 **1084.95/token**。这条明文让 guided 的概率阶段更容易命中，但少数低概率位置及误前缀仍能主导 CPA 成本。因此此次数据不能支持“两种方法在自然语言上都必然更快”的结论。

## 概率排名与批量多算核查

针对“多数 token 应在概率前 50，为何仍查询这么多”的核查见 [逐位置排名](rank_audit.json)。官方源码不是每算一个候选立即停：它先算完整逻辑批（默认 256），再取概率序中首个通过者。当前 CPA 按这个规则运行，所以第 1 名通过也会计入 256 个已计算候选；手机分成两次物理 128 调用。

本次 CPA 共计算 22,784 个候选。其中，沿本次自身恢复前缀，把每位置首个通过者的排名相加是 **17,953**，逻辑批尾部已算但不用的候选为 **4,831**。这只是从实际记录提取的顺序检查数量，不能当作已测的逐 token 执行耗时。

| 位置 | token | CPA 中真 token 的概率排名（1 起） | 完整批实际计算 |
| --- | --- | ---: | ---: |
| 1 | `write` | 12,976 | 13,056 |
| 10 | ` leaves` | 332 | 512 |
| 21 | ` goa` | 4,250 | 4,352 |

`write` 与 ` goa` 两处的首个通过者排名合计 17,226，占 17,953 的 **95.95%**。即使按记录中的顺序逐个检查，候选量仍主要集中在这两处；其余 19 个位置首个通过者的排名合计只有 727。不能将批量多算解释成全部候选差距。

还必须区分两条恢复路径：guided 的正确前缀下有 **18/21** 个真 token 位于前 50；CPA 这次自己的前缀下是 **16/21**。CPA 在第二个位置接受了 ` a`，之后与 guided 的 ` an` 前缀不同。例如第三个 ` email` 在 guided 的排名为 2，在 CPA 为 260。后续不能直接套用 guided 的排名去推断 CPA 应查询多少。

这次排名异常低的第一个词 `write` 使用相同公开前缀，已经在记录中实际出现在第 12,976 位；不是因批次补齐才变成低排名。低排名的具体模型原因未通过额外消融确认。

## 配置与判定边界

- 完整原始词表 262144，不按语言/字符过滤；逻辑 batch 上限 256，物理 `prefill_128`；无 600 次查询上限，seed=20261019。
- guided：50 概率 + 150 随机初始候选，每轮 20 个 ridge 提议；原始数值 K+V 拼接 **L2 < 4**，不是 4 LSB；取完整接受阶段中距离最小的通过者。
- CPA：官方规则 NPU 移植，概率序中首个通过 K/V 双阈值者，rank=8、1% 容差。仍用独立文本 **8 位置×1024 候选 pilot 校准**，未完成全文全词表校准。有效 K 阈值 0.3821817103、V 阈值 10.3494870758，与密文实验相同。
- 两者停止规则及提交方式不同；CPA 保留所有层的候选 KV，guided 查询目标层并重新 decode 提交。这是现有两套方法的端到端比较，并非仅替换搜索顺序的同阈值对照。
- 目标观测为真实 INT8 KV，按各张量的 scale/zero-point 还原原始数值计算距离；不把反量化 L2 当作整数码的 LSB 距离。阈值通过不代表理论唯一性，正确率来自事后独立标签。

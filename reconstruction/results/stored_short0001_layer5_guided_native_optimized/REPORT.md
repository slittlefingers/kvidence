# 手机端优化：同一条第 5 层密文样本

Gemma 4 E2B、Pixel 10 NPU、数据库样本 0001 的 109-token 密文恢复，在线耗时从上轮持久连接版 **222.327 秒降到 117.365 秒**，本次约 **1.89 倍**加速。相对最初文件通信的 610.764 秒，累计约 **5.20 倍**。独立评估仍为 **109/109 正确**。

## 条件与结果一致性

三次运行使用相同已保存观测（APK 回复后快照中的目标密文位置）、第 5 层、相同模型和完整 262144 词表、逻辑 batch=256/物理槽位=128。guided 仍用 50 个模型概率候选 +150 个随机种子、20 个 ridge 提议、seed=20261019、拼接原始 K+V 数值 L2<4，无默认查询预算上限。

逐位置比较三次运行的查询序列、查询次数、选中 token ID、接受的原始 KV 字节、接受/提交距离和 commit/query 一致性：全部相同。每次均查询 16,530 个候选、388 次物理候选调用，全部接受和提交距离为 0。完整词表、候选顺序和停止条件没有缩减。恢复使用自己的已恢复前缀，没有读取私有标签或加载目标前缀 KV。

## 改动

- 连续后缀内存按块复制，替代逐元素计算 stride 地址与复制；保留非连续布局、padding 和部分范围写入的正确性。
- 同一位置缓存 RoPE/mask 及批量上下文输入。388 次候选查询仅构造 109 次批量上下文，复用 279 次；109 次提交也命中该位置的单步上下文。reset 强制失效，不能跨不同等长前缀复用。
- embedding 缓存返回引用，批输入预留空间；减少临时副本。原 1024 项缓存上限不变。
- CPA 返回目标层 KV 时复用已保存的全层候选切片，保持 retained commit 规则。

实际实现与计时字段说明见 [NATIVE_OPTIMIZATION.md](../../NATIVE_OPTIMIZATION.md)。

## 现在时间花在哪里

本次 388 次候选查询，worker 内部共 **56.048 秒**，其中主 prefill 调用 **24.335 秒**。高层步骤为：

| 候选查询步骤 | 时间 |
| --- | ---: |
| embedding/PLE 获取、缓存访问与批量拼装 | 20.164 s |
| 位置上下文准备及写入 | 4.548 s |
| 候选 embedding 输入写入 | 0.682 s |
| 候选 KV 读取 | 2.426 s |
| 候选切片与返回数据打包 | 0.900 s |
| 主 prefill 调用 | 24.335 s |
| 其余管理、释放等 | 2.993 s |

embedding/PLE 准备包含 CPU 子模型调用：embedder 1.179 秒、per-layer embedder 5.397 秒；它们已包含在 20.164 秒内，不能再次相加。该阶段剩余还有输入输出读写、缓存管理、复制与分配等，没有把这些全部当作 embedding 数学计算。

此外，109 次 commit 的 worker 时间为 12.211 秒（主 decode 6.676 秒、输出读取打包 4.358 秒、KV 追加 1.021 秒等）；109 次完整词表 ranking 的 worker 时间为 16.254 秒。主机候选评分 20.333 秒。下一轮优化需要针对 embedding 批量拼装和完整排名/主机评分，不应再把所有耗时归为通信。

## 证据和限制

- [独立正确性评估](evaluation.json)：109/109；[机器可读分解及轨迹一致性](native_comparison.json)；[每次 RPC 的细分计时](device/rpc.jsonl)。
- [同 APK reference/optimized 对照](../native_validation_20261019/validation.json)使用公开前缀和固定候选，覆盖重复查询、不同 batch 数量、跨物理批的 CPA 提交、提交后查询、不同等长前缀 reset；所有对应 KV 和完整排名逐字节相同，也与上轮 APK 保存的共享检查结果相同。
- 该短对照的 9 次混合候选查询，worker 4.054 → 1.474 秒；通用 buffer 读写复制（嵌套指标）3.154 → 0.141 秒，确认逐元素张量复制是参考路径的重要瓶颈。不能把这个短样本的比例当作全部输入的比例。
- 48 项主机测试通过；其中原生 C++ 复制测试比较 2000 种布局及部分写入，检查 padding 未改变。
- 新 APK/optimized 模式重新采集独立 8 位置 × 1024 候选 CPA pilot，阈值与历史资产相同：[校准](../../assets/cpa_gemma4_pilot_native_optimized/calibration.json)。该资产仍需要 `--allow-pilot-calibration`，不是全文全词表校准。
- 本次完整重跑 guided；CPA 另做有限接口/集成检查，没有重跑这条密文的完整 CPA 基线，不能据此更新两种搜索算法的速度比。
- 完整耗时对比是历史各一次运行与当前一次运行，不是随机交错重复试验；频率、热状态、内存与主机调度都有波动。加速比例仅是本样本的观测值。`decoder_seconds` 为 LiteRT 主运行调用墙钟时间，包含运行时/驱动开销，不是纯 NPU kernel 时间。

# 候选集扩大到 10,000：复核结果

2026-10-16。沿用 [2048 候选实验](README.md) 的冻结 TinyStories 小模型、已知正确前缀、单个未知 Token、float32 深层 KV 和四种搜索方法。没有增加训练数据或调节代理超参数。

## 本轮设置

- 候选集从 **2048 → 10,000** 个已有英文/数字 Token 片段；原模型完整词表仍为 50,257。
- 所有方法仍共享最初 **200 次随机 KV 查询**；后续每批 20 次，预算点为 200、220、240、300、400、600。初始探测比例由约 9.8% 降至 2%。
- 第 4、8 层；同样的岭回归代理（64 维 embedding → 128 维 K+V，含截距，ridge=0.01）。
- 首轮 seed=20261017，每种目标分布、每层 16 个目标；独立复核 seed=20261018，每种目标分布、每层 32 个目标。
- 总计首轮 64 个、复核 128 个 layer/target cases。相同目标分别测两层，不应把它们当作完全独立的目标样本。
- 候选集和目标在各规模下按固定种子重新生成，**跨规模不是同一目标的配对实验**。因此恢复率差异只能作为描述性比较，不能全部归因于词表规模。

## 与 2048 候选的描述性比较

均为独立复核的均匀目标组，每层 32 个目标；下表列 KV 引导结果。

| 层 | 2048 候选 @220 | 10,000 候选 @220 | 2048 候选 @600 | 10,000 候选 @600 |
| --- | ---: | ---: | ---: | ---: |
| 第 4 层 | 28/32 | 27/32 | 32/32 | 32/32 |
| 第 8 层 | 25/32 | 18/32 | 32/32 | 32/32 |

本轮在查询 2.2% 的候选时，第 4、8 层分别恢复 84.375%、56.25% 的均匀目标；查询 6% 时两层均达到 32/32。首轮均匀目标 @220 分别为 13/16、10/16，@600 均为 16/16，趋势一致。

这支持“少量实测 KV 提供有用候选排序”的假设，但第 8 层早期恢复率更低，说明固定 200 点的代理不总能一次定位目标。

不能据此认定代理始终优于语言概率：概率目标在第 8 层 @220，语言概率是 28/32，KV 引导只有 11/32；@600 仍分别为 32/32、31/32。第 4 层 @220 KV 引导为 30/32，高于概率的 28/32，但 @600 代理仍有 1 个目标未恢复。

## 校验与边界

- 所有轨迹均确认：候选数量 10,000；各方法共享相同初始 200 个候选和距离；600 次预算没有重复查询；所有距离为有限非负值。
- “查到正确候选”与“按真实 KV 最小距离精确选中目标”在所有预算点一致。没有靠目标 ID 指导候选选择。
- 仍是 64 维 embedding 小模型，200 个观测超过含截距的 65 个输入项；不能直接外推到几千维 embedding 的大模型。
- 仍未测试完整词表、量化/缺失 KV、未知前缀、多 Token 联合恢复或实际密码。
- 概率基线被要求共享最初的随机 200 次查询，不代表其从第 1 次就按概率搜索的最佳总体策略；也不是论文 Collision+ 原实现。
- 比较主要依据原模型查询数，不声称端到端速度倍数。对 10,000 个 embedding 的代理打分本身也有计算成本。
- 两个随机种子运行并行执行，因此日志中的约 9.71 秒、18.86 秒含 CPU 资源竞争，不宜直接与之前串行运行时间比较。

## 文件与复现

- [`results_10000/metrics.json`](results_10000/metrics.json)：首轮指标。
- [`replication_10000/metrics.json`](replication_10000/metrics.json)：独立复核完整预算曲线。
- [`results_10000/trials.json`](results_10000/trials.json)、[`replication_10000/trials.json`](replication_10000/trials.json)：逐目标查询索引及实测距离。
- 两个目录的 `candidates.json` 保存完整候选 ID/文本。
- [`run_10000.log`](run_10000.log)、[`replication_10000.log`](replication_10000.log)：运行日志。
- [`search.py`](search.py) 的搜索算法未因本次扩大候选集而修改；[`validate.py`](validate.py) 已支持按结果元数据检查不同词表大小。

在工作区根目录运行（为保留现有结果，可改用新的输出目录）：

```sh
kvidence/experiments/kv_inverse_tiny/.venv/bin/python \
  kvidence/experiments/kv_guided_search/search.py \
  --candidates 10000 --seed 20261017 --trials-per-scenario 16 \
  --output kvidence/experiments/kv_guided_search/results_10000

kvidence/experiments/kv_inverse_tiny/.venv/bin/python \
  kvidence/experiments/kv_guided_search/search.py \
  --candidates 10000 --seed 20261018 --trials-per-scenario 32 \
  --output kvidence/experiments/kv_guided_search/replication_10000

kvidence/experiments/kv_inverse_tiny/.venv/bin/python \
  kvidence/experiments/kv_guided_search/validate.py \
  results_10000 replication_10000
```

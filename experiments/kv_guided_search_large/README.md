# 更大模型与 embedding table 的 KV 搜索实验

沿用 `../kv_guided_search` 的问题：已知正确前缀和一个目标 token 的深层 KV，用 200 个候选 token 的实测 KV 拟合 embedding → KV，再给未查询的候选排序。原始语言模型及 embedding 均冻结；不是重新训练语言模型，也不是把整个 KV 词典预先算出来。

## 模型与规模

| 项目 | 之前 | 本次 |
|---|---:|---:|
| 模型 | TinyStories-1M | Qwen2.5-0.5B（base） |
| 实际参数量（含 embedding，权重共享只计一次） | 3,745,984 | 494,032,768 |
| embedding table | 50,257 × 64 | 151,936 × 896 |
| embedding 元素数 | 3,216,448 | 136,134,656 |
| Transformer 层数 | 8 | 24 |
| 观察层（从 1 开始） | 4、8 | 12、24 |
| 每 token 每观察层 K+V 维度 | 128 | 256 |
| 搜索候选数 | 10,000 | 10,000 |
| 初始查询 / 最大总查询 | 200 / 600 | 200 / 600 |

embedding 元素数约增大 42.3 倍，维度增大 14 倍，词表行数约增大 3.02 倍。**全模型的 embedding table 与实际参与搜索的候选子集是两个不同的量。** 本次扩大前者，候选数保持 10,000，以避免同时改变所有因素。

Qwen 固定版本：`060db6499f32faf8b98477b0a26969ef7d8b9987`。

- [模型仓库](https://huggingface.co/Qwen/Qwen2.5-0.5B)
- [固定版本配置](https://huggingface.co/Qwen/Qwen2.5-0.5B/blob/060db6499f32faf8b98477b0a26969ef7d8b9987/config.json)
- 权重文件 `model.safetensors`：988,097,824 bytes。
- SHA-256：`88c142557820ccad55bb59756bfcfcf891de9cc6202816bd346445188a0ed342`，已与 Hugging Face LFS 元数据核对。
- 运行时将原 BF16 权重转为 FP32，读取完整 FP32 KV；不等同于手机 NPU 量化 KV。

## 方法与适配

每个种子、每种目标分布各 16 个目标，分别观察第 12、24 层。主实验种子 `20261017`，独立重复种子 `20261018`；候选池随种子独立抽取。试跑 `pilot/` 只有每种分布一个目标，不纳入正式汇总。

目标分布分别为候选集均匀采样、按模型条件概率采样。四种方法共享相同初始 200 个候选的实测 KV：随机、按模型条件概率排序、KV 代理模型、打乱 token 与 embedding 对应关系的负对照。之后每批查询 20 个真实候选，累计到 220、240、300、400、600；不因提前命中而停止。最终输出是已查询候选中真实 KV 距离最小的 token。

代理模型保持同一个带截距的标准化 ridge 回归，正则强度 `0.01 × 已查询样本数`。因为 embedding 维度 896 大于查询样本数，改用等价的对偶解，以求解较小的样本空间矩阵；截距仍不正则化。不是改成另一种搜索方法。对独立随机数据已核对原始空间解与对偶解前 100 个排序一致。

Qwen 使用 GQA，读取的是实际 2 个 KV heads × head_dim 64 × K/V，而不是复制成 14 个 query heads。为节省计算，查询第 12 层时只运行前 12 层；概率基线始终使用完整 24 层。

候选来自原模型有效 token：解码后为一个空格开头的 1–16 个英文字母/数字，或无前导空格的 1–3 个数字，同时要求 encode/decode 单 token 往返一致。共有 41,393 个符合条件的 token；其中抽取 10,000 个，并保证包含单个英文字母和数字。

Qwen 的 `" 1"` 编码为“空格 + 1”两个 token，因此本次数字候选是 `"1"` 等单 token。不能沿用旧 tokenizer 的前导空格数字假设。已逐一检查全部 10,000 候选与 8 个前缀的拼接编码边界；实际候选和前缀保存在输出中。

## 验证与复现

复用 `../kv_inverse_tiny/.venv`（torch 2.6.0、transformers 4.51.3、numpy 2.2.6；依赖锁定文件在该目录）。Apple MPS 做 FP32 模型前向，CPU 做 ridge 拟合和排序。两次正式运行同时执行，因此耗时不能用作与旧实验的严格速度比较。

```bash
cd /path/to/litertlm
PY=kvidence/experiments/kv_inverse_tiny/.venv/bin/python
EXP=kvidence/experiments/kv_guided_search_large
"$PY" "$EXP/download_model.py"
PYTORCH_ENABLE_MPS_FALLBACK=1 "$PY" "$EXP/check_oracle.py"
PYTORCH_ENABLE_MPS_FALLBACK=1 "$PY" "$EXP/search.py" --trials-per-scenario 16 --seed 20261017 --output "$EXP/results"
PYTORCH_ENABLE_MPS_FALLBACK=1 "$PY" "$EXP/search.py" --trials-per-scenario 16 --seed 20261018 --output "$EXP/replication"
"$PY" "$EXP/validate.py"
"$PY" "$EXP/summarize_results.py"
```

`check_oracle.py` 比较完整输入前向与前缀缓存查询，以及单独查询与批量查询；第 12、24 层均通过，并确认原前缀缓存长度不变。结果见 `oracle_validation.json`。

`validate.py` 独立检查每条轨迹的候选唯一性、共享初始观测、预算、有限距离、命中后的正确识别及汇总数字。

输出：`metrics.json`（配置及汇总）、`candidates.json`（候选 token 映射）、`trials.json`（全部查询顺序与真实 KV 距离）。`run.log`、`replication.log` 为正式日志；大模型权重单独在忽略提交的 `model/`。

## 适用范围

- 是已知正确前缀、单个未知 token、可访问原模型 embedding/权重的白盒实验；不代表未知整段前缀或长密码已经恢复。
- 本次观察中层及最后一层，不使用首层 KV。
- 完整 FP32 KV 和短前缀比实际 NPU 量化、截断、噪声及长上下文场景简单。
- 模型架构、训练分布、位置编码、KV head 数、tokenizer 都同时改变；不是仅改变参数量的受控因果实验。
- 200 个样本对 896 维 embedding 是欠定的；ridge 可求解，但成功与否依赖模型是否存在可利用的低维相关结构。
- 候选集仍限制英文/数字，不包含整个 151,936 行词表；不能把子集命中率当成全词表命中率。
- 概率基线在共享的初始 200 次随机查询之后才按概率排序；不是从第 1 次查询就用概率排序的最优实现，也不是论文 Collision+ 的完整复现。
- 代理排序仍会扫描所有候选 embedding；减少的是昂贵模型 KV 查询，不是消除全候选算术运算。
- 每种分布每种子 16 个目标，跨层观察同一目标；两层不能算作独立样本来放大统计量。两个候选池中目标也不同，不是与旧模型的同目标配对比较。

## 正式结果与解释

两次正式运行各 64 个“目标 × 层”案例，均通过独立轨迹审计及汇总重算。每种目标分布、每个观察层合计 32 个目标；不将同一目标的两个层合并成 64 个独立目标。

完整预算曲线见 [RESULTS.md](RESULTS.md)，机器可读汇总见 [combined_metrics.json](combined_metrics.json)。以下是均匀随机目标的精确恢复数：

| 方法 / 观察层 | 总查询 220（200 初始 + 20） | 总查询 600 |
|---|---:|---:|
| KV 方向，第 12 层 | 11/32（34.4%） | 31/32（96.9%） |
| KV 方向，第 24 层 | 28/32（87.5%） | 32/32（100%） |
| 随机，两层均相同 | 0/32 | 2/32 |
| 语言概率，两层均相同 | 0/32 | 0/32 |
| 打乱 embedding，第 12 层 | 0/32 | 0/32 |
| 打乱 embedding，第 24 层 | 0/32 | 1/32 |

随机目标的两次独立运行中，第 12 层在 600 次分别恢复 15/16、16/16，第 24 层均为 16/16；结果不是只来自某一次种子。第 24 层在 400 次时已恢复 32/32。

对按模型语言概率抽样的目标，220 次时概率排序恢复 28/32，KV 方向第 12/24 层分别恢复 13/32、14/32；600 次时概率排序恢复 31/32，KV 方向分别为 31/32、32/32。因此 KV 方向不是所有分布都在小预算下优于语言概率；其主要价值在于低语言概率目标仍有可利用的几何信息。

结论是：**在这个更大的预训练模型上，200 个实测 embedding/KV 对仍足以提供有效搜索方向。** 896 维映射在 200 个样本下欠定，并未阻止候选排序成功；排序不要求精确重建整个映射。但本次没有测量映射有效秩，也没有证明整个 896 维空间都已学会。第 12 层在小预算下较弱，而第 24 层较强，也说明“越深越难”不能在不同模型上直接假定。

这仍然是 10,000 候选、已知正确前缀、完整 FP32 KV、单 token 的有限样本实验。32/32 是本次样本结果，不是总体成功率保证；全 151,936 行词表搜索、未知前缀、连续随机密码及实际 NPU 量化 KV 尚未验证。

两次正式进程同时运行，日志记录各约 211 秒、207 秒；这些是整批实验运行时间，包含四种方法与重复前向，不能用来声称对 Collision+ 的速度提升。

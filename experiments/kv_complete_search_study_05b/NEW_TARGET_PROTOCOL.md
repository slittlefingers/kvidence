# 新目标检验：冻结后的附加验证

在旧案例的局部诊断和经验校准结果已经产生、但本文件所述新目标尚未生成和运行时，固定以下附加检查。旧结果保留，不将其改称新确认结果。

- 目的：检查“局部 oracle 界有效、经验校准仍可能漏解”的发现是否在未用过的目标 token 上持续出现。
- 每个现有候选池选择 8 个新目标，共 16 个 token、两层合计 32 个目标/层案例。
- 按真实词表 token ID 排除之前 development 和 confirmation 的所有目标，并排除新目标之间的跨候选池重复。
- 固定随机种子偏移 `14000000`；逐试验目标抽样种子 `pool_seed + 14000000 + trial*101`。
- 初始 200 个查询：`pool_seed + 14100000 + trial`；后续随机种子：`pool_seed + 14200000 + trial`。前缀沿用 `trial % 4`。
- 两种方法仍为原冻结线性代理与此前冻结 RBF 方法；原方法直接调用原函数。查询预算、批量、代理超参数不变。
- 局部界、经验校准、审计全部使用本轮 README 已固定的参数；不依据新目标结果调参。
- 新目标沿用相同模型、候选池和四个前缀；因此是新 token 目标检验，不是跨模型、未知前缀或新语料泛化测试。
- 主比较仍为第 12 层、ε=0.25、600 点搜索、32 个距离组、额外 600 点校准；每例 5 个校准随机重复。其余预设配置全部保留。
- 新目标结果单独保存为 `fresh_results/`；不与旧案例混合后声称一个独立样本量。

方法脚本、旧结果和本协议的哈希会在运行前固定，结束后复核。

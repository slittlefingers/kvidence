# Qwen2.5-0.5B：独立候选选择策略实验

研究目标补充：最终需要找全容差内的候选。原报告的单目标命中结果只作为辅助证据；
用户重申目标后，已另写 [找全候选的事后评价](ALL_SOLUTIONS.md)，不改写下面的原始预设或原方法。

本实验保留 `../kv_guided_search_large/search.py` 的原方法作为冻结基线，**不修改原代码或参数**。
目标是研究相同真实 KV 查询预算下，能否更早找到目标、更快降低实际距离、找到更多容差内候选。
这里不尝试建立找全证书，不使用新策略的预测结果永久删除任何未查询候选。

## 在运行前固定的设置

- 复用 `../kv_linfact_05b/data/` 的 Qwen2.5-0.5B 原模型 FP32 KV 表。
- 两个 10,000 候选池、四个已知正确短前缀、观察第 12/24 层，每次恢复一个未知 token。
- `development`：上一轮的 16 个目标，保留相同初始 200 个查询。
- `confirmation`：另抽 16 个目标，与 development 的目标 ID 不重叠；候选池和前缀仍共享。
  不是新模型或未知前缀泛化测试。确认组不会用于调参或挑选方法；同时公布全部方法。
- 每批 20 个新候选，最多 600 次；检查点 200、220、240、300、400、600。
- 首要指标为正确 token 命中数 @220；同时报告 @240、@600、真实距离、容差集合召回和搜索开销。
- 数据是离线隐藏答案表。搜索只能通过计数 oracle 读取查询行，不接收目标索引或所有真实距离。
  完整表只在搜索返回后用于评分。搜索耗时不等于在线模型推理耗时。
- 容差评估使用 `max(abs(KV-target))/max(abs(target)) <= 0.10 或 0.25`。
  无额外噪声、无 INT8，不把阈值解释成 LSB。

## 方法及冻结参数

| 名称 | 与原方法的区别 |
|---|---|
| `original` | 直接调用原函数 `proxy_ranking`，896 维 embedding、ridge=0.01、预测原单位 KV 的 MSE 排序 |
| `random` | 共享初始查询后，均匀无重复随机查询 |
| `linfact_vector_reference` | 沿用上一轮 PCA32 + 经验区间 + G 设计适配，搜索 epsilon 固定 0.10；仅为参照，不是本轮新方法 |
| `ridge_linf` | 同一个原始代理拟合，把候选排序从预测 MSE 改为预测最大坐标绝对差，检查距离目标的影响 |
| `target_weighted_ridge` | 保留原特征尺度；按已查询候选的真实 KV 距离加权拟合，以检验目标附近的拟合是否更有效 |
| `linear_rbf` | 线性核加 RBF 核，拟合 KV 向量，检验非线性关系；用预测 MSE 排序 |
| `target_design_16_4` | 相同原代理，每批先取预测最近的 16 个；再在预测前 200 名中按条件特征方差选 4 个，逐个考虑本批已经选中的点 |

所有新增方法使用完整 896 维 embedding 和全部已查询训练样本，不沿用上轮的 PCA32 和 50 点校准拆分。
它们是本项目提出用于比较的工程变体，不是对某篇论文定理的复现。

`target_weighted_ridge`：用已测原单位 KV 的 MSE 距离 `d_i`，令 `q` 为这些距离的 25% 分位数，
`w_i = 0.1 + exp(-d_i/max(q,1e-12))`，再令权重均值为 1。
在原标准化输入上做带权中心化、带截距岭回归，惩罚仍为 `0.01*n`。

`linear_rbf`：只用已查询样本确定输入均值/尺度和核带宽。
`K(x,z) = xᵀz + 896 * exp(-||x-z||²/s)`，`s` 为训练样本非对角平方距离的中位数。
对核做训练集中心化以保留截距，惩罚仍为 `0.01*n`。不按测试结果搜索带宽。

`target_design_16_4`：令 `X` 为当前标准化并中心化训练特征，`P` 为预测前 200 名的特征，
`lambda=0.01*n`，构造
`C = P Pᵀ - P Xᵀ (X Xᵀ + lambda I)⁻¹ X Pᵀ`。
先按 16 个贪心选择条件化，再按最大对角元逐个选 4 个：
`C <- C - C[:,j] C[j,:] / (lambda + C[j,j])`。
这是特征信息量启发式，不声称该方差是模型真实 KV 误差的置信界，也不据此排除候选。

## 对照与审计

- 原函数源码 SHA256 在运行前后核对；原方法直接调用，不重新实现作为基线。
- 在 development 组核对原方法完整查询顺序与上一轮保存的轨迹逐项相同。
- 确认组目标生成种子加 `900000`，初始查询独立生成，所有方法共享。
- 去重按所有候选池的真实词表 token ID 执行，而非仅比较池内索引。
- 验证新预测实现与原排序一致、权重退化为 1 时与原预测一致、核中心化一致，以及设计协方差更新。
- 独立从原始 KV 重算所有指标，核对无重复查询、相同起点、查询预算和确认组目标不重叠。
- 不根据确认组结果改超参数。小样本对比只报告实际表现，不能证明普遍优于原方法。

## 运行

从本目录执行：

```bash
PY=../kv_inverse_tiny/.venv/bin/python
$PY experiment.py run
$PY validate.py
$PY online_check.py
$PY validate.py
$PY report.py
```

报告为 `RESULTS.md`；逐案例数据与查询轨迹保存在 `results/`。
原模型、原代理和上一轮 LinFACT 实验均保持原样。

## 后续实际模型计时抽查

对确认组 seed=20261019 的前四个目标、两层，比较原方法与三个主要新策略，逐次查询真实模型，
不使用表回放替代查询。每个案例的方法顺序固定随机打乱，CPU 四线程，每种方法测一次。
计时包含初始 200 个候选及后续真实前向、拟合和选择；排除模型加载、前缀缓存准备和预热。
另记录首次命中批次结束时的实际时间。每条返回 KV 在搜索结束后与离线表核对。
这是小规模运行成本抽查，不是稳定的硬件性能基准，不代表 Pixel NPU 性能。

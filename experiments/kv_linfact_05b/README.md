# Qwen2.5-0.5B：LinFACT 风格集合搜索对比

这是一次 **LinFACT-G 思路的工程适配实验，不是原论文算法/定理的完整复现**。
目标是比较主动实验设计是否有助于找回 token、找全近最优候选，以及经验误差界是否会误删真解。

## 预先固定的设置

- 复用本地 `../kv_guided_search_large/model` 的 Qwen2.5-0.5B，版本
  `060db6499f32faf8b98477b0a26969ef7d8b9987`；FP32 权重计算和 FP32 KV。
- 两个候选池种子 `20261019, 20261020`，各 10,000 个英文/数字 token。
- 每个池 8 个均匀抽取目标，分布于四个已知正确的短前缀；同一目标同时观察第 12/24 层。
- 每次恢复一个未知 token，不使用首层，不模拟未知前缀或整段秘密恢复。
- 所有方法共享初始 200 次查询；每批最多新增 20 次；预算 200/220/240/300/400/600。
- 距离 `D(v) = max(abs(KV(v)-target)) / max(abs(target))`，epsilon 固定为 0.10 和 0.25。
  答案是全候选中 `D(v) <= min(D)+epsilon` 的集合。未添加观测噪声；不是 INT8/LSB 实验。
- 对 LinFACT 适配方法，初始 200 个查询中固定 50 个用于校准，150 个用于拟合；50 个校准点永不加入拟合。
- PCA 32 维只读取候选 embedding，不读取 KV/目标标签；附加截距后 33 维。
- 经验误差包络为校准集最大标准化残差的 1.5 倍，乘以候选预测杠杆因子。
  此系数在查看新实验结果前固定，**没有全候选/自适应过程的 PAC 覆盖保证**。

## 五种方法

1. `random`：共享初始样本后的随机无重复查询。
2. `kv_surrogate_full`：原来的完整 896 维 embedding → KV ridge + MSE 排序。
3. `kv_surrogate_pca`：相同 ridge 搜索，但输入改为 PCA 32 维，控制降维影响。
4. `linfact_g_scalar`：PCA 特征 → 标量真实距离的 OLS；经验区间 + LinFACT 的近最优集合分类规则。
5. `linfact_g_vector`：PCA 特征 → KV 向量的 OLS；向量无穷范数误差包络转换成距离上下界，使用相同集合规则。

后两种方法按活动候选上的近似 G-optimal design 分配查询。用 D-optimal vertex-direction
迭代和 Kiefer–Wolfowitz 的最大杠杆证书检查设计质量，记录每次的 `max_leverage/rank`；
有限批次按设计权重无放回采样。只计算仍未查询的活动候选，避免对确定性模型重复前向。
原论文的精确取整、每轮精度减半和采样次数公式未照搬。这里采用累积数据、固定预算以及
经验模型偏差界，故不得把论文的置信度/最优查询复杂度直接写到本实验结论中。

PCA 32 是本次预算下的工程选择：完整特征含截距为 897 维，而初始拟合只有 150 个点，
无法直接使用满秩 OLS。这种截断不等同于论文的无损子空间投影，会引入额外模型偏差。
因此同时提供 PCA 32 的原 KV 代理作为对照；本次没有调节 PCA 维数或校准倍数来优化结果。

具体经验区间可写为：令训练信息矩阵为 `V = XᵀX`，候选特征为 `φ(v)`，
杠杆值为 `h(v) = φ(v)ᵀ V⁻¹ φ(v)`。校准点残差的最大坐标绝对值记为 `r(j)`，则
`b = 1.5 × max_j r(j)/sqrt(1+h(j))`，候选半径为 `R(v) = b × sqrt(1+h(v))`。
标量版本对归一化距离直接拟合；向量版本先预测归一化 KV，再以无穷范数计算预测距离。
距离包络为 `L(v)=max(0,D_hat(v)-R(v))`、`U(v)=max(0,D_hat(v)+R(v))`。
已查询候选的上下界直接替换为真实距离。

当 `U(v) <= min(L)+epsilon` 时标为好候选；当 `L(v) > min(U)+epsilon` 时排除。
最小值在当前活动集合上计算。**这些分类规则的正确性以同时覆盖为前提，校准残差本身
不保证此前提成立。** 全部分类才停止，否则到预算上限留下未决候选。

## 防止评分信息泄漏

先生成全部候选的深层 KV 表，作为**离线 benchmark 的隐藏答案**。
搜索函数只通过带查询记账的 oracle 取得所选行；不接收目标索引、全表或全候选真实距离。
完整表仅由评分程序读取，用于审计误删、集合覆盖和区间覆盖。完整表生成的所有模型前向
另外记录，不能把这项离线成本说成算法消除了。

因此主比较是 **逻辑模型查询数 + 搜索计算时间**。搜索中的表查找时间不是模型推理时间；
它们的和也不能作为端到端攻击时间。本次不宣称手机 NPU 速度。

## 结果解读

- `target_queried`：是否真正查询过目标 token。
- `nearest_recovered`：已查询候选中，真实最大单维距离最小的 token 是否为目标。
- `confirmed_good`：区间规则认定的近最优候选，包括未经前向的预测判断；需要独立审计。
- `possible`：尚未被排除的所有候选；它包含真解不等于已确认找全。
- `false_eliminations`：被永久排除的真正近最优候选数量。
- `stopped`：所有候选都已分类；必须同时检查 `exact_set`，防止错误早停。
- 基线只输出已经查询且距离距已查询最小值不超过 epsilon 的候选，没有“找全”证书。
- `interval_coverage` 事后检查所有候选，不把平均覆盖率当作同时覆盖保证。

## 运行

```bash
PY=../kv_inverse_tiny/.venv/bin/python
$PY experiment.py build --device cpu
$PY experiment.py run
$PY validate.py
$PY report.py
```

从本目录运行。已有模型和依赖，无需下载。结果见 `RESULTS.md`、`results/summary.json`。
`data/` 为隐藏答案表；`results/traces/` 为逐次查询与区间快照，均在本地忽略提交。
